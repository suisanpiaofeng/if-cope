# Harness P0 改造 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 IF.Cope 补齐为可用的 AI 编程 harness（P0）：skill 上传/批量/对话安装、工作区文件工具与受限命令执行、三档确认安全底座、会话重命名与模型配置档。

**Architecture:** 工作区 `data/workspace/` 为文件/命令工具的唯一根（路径安全双保险）；确认流用服务端挂起表 + `/api/agent/confirm` 解除（60s 超时自动拒绝）；skill 导入走"预检 409 → 逐项决策 → 提交"两步式；模型配置档物化到既有 settings 字段保持全量兼容。UI 融入工作台（资源栏视图切换 + 对话确认卡）。

**Tech Stack:** 不变（Next.js 15 / TS / better-sqlite3 / Tailwind）；零新依赖；命令执行用 node:child_process。

**Spec:** `docs/superpowers/specs/2026-11-12-harness-p0-design.md`

## Global Constraints

- 零新依赖；UI 文案中文、风格沿用现有 Tailwind 类
- 工作区 root：`settings.workspacePath || process.env.IFCOPE_WORKSPACE_DIR || <cwd>/data/workspace`；所有路径 `resolveInWorkspace()` 前缀检查，越界 throw「路径超出工作区」
- 三档：`readonly` 免确认 / `reversible` 确认 / `destructive` 红色强确认；`confirmMode` 默认 `writes`
- run_command：黑名单 `deny` 硬拒（不给确认）；白名单 `readonly` 直跑；其余 `destructive`；cwd=工作区 root；超时默认 30s（≤120s）；输出合并截 20k
- 命令分级规范化：命令串 `trim().toLowerCase()` 并去除引号/多余空白后再匹配黑名单
- TDD：`scripts/verify-workspace-fn.mjs` / `verify-confirm-fn.mjs` / `verify-skill-import.mjs` 裸 Node 跑纯逻辑；挂进 `npm run verify`
- 每任务收尾 `npm run verify && npm run typecheck` 全绿 + commit（中文 `feat(harness): ...`）
- 挂起确认表放模块级 Map（nodejs runtime 单进程），超时 60s 自动拒绝

## Review Focus

1. **路径穿越/越界**（`../`、绝对路径、盘符、`a/../../b`）打 read/write/edit/list/run cwd → 一律「路径超出工作区」拒绝，绝不触碰工作区外 — T1 verify 断言 + T3 步骤
2. **run_command 黑名单绕过**（大小写、引号包裹、`&&` 串联、`del /f /s` 变体）→ 规范化后判级，任一片段命中黑名单即 deny — T2 verify 绕过样本
3. **确认挂起死锁**（用户不点/刷新页面）→ askConfirmation 60s 超时自动拒绝、循环继续回喂文本不卡死 — T2 verify 超时分支 + T5 冒烟
4. **导入冲突派生**（同批同名、`name-2` 也被占、无 frontmatter 纯 md）→ planImport 纯函数取首个空位、元数据自动生成正确 — T6 verify
5. **模型配置档切换兼容**（切档后全部既有读取点生效、遮罩 key 语义不变、空 temperature 不传参）→ T9 冒烟清单钉死

**Interfaces:**
- Consumes: 无
- Produces:
  - `type Risk = "readonly" | "reversible" | "destructive" | "deny"`
  - `classifyCommand(cmd: string): Risk` — 规范化（lowercase+去引号+压空白）后：黑名单→`deny`；白名单只读→`readonly`；含写/删/push 等→`destructive`；其余→`reversible`
  - `classifyTool(name: string, args: Record<string, unknown>): Risk` — TOOL_RISK 表；`run_command` 委托 `classifyCommand`
  - `TOOL_RISK: Record<string, Risk>` — list_files/read_file/search_code/load_skill/list_library/list_preferences → readonly；write_file/edit_file/move_source/move_artifact/create_category/todo_write/save_preference/delete_preference/generate_summary/create_skill/install_skill → reversible；delete 系 → destructive（delete_preference reversible）
  - `askConfirmation(callId: string, risk: Risk, name: string, args: Record<string, unknown>): Promise<boolean>` — 挂起到全局 Map，60s 超时 resolve(false)
  - `resolveConfirmation(callId: string, approve: boolean): boolean` — 解除挂起；未知 callId 返回 false
  - `confirmModeAllows(mode: string, risk: Risk): boolean` — `none`=全放行；`writes`=reversible+destructive 需确认；`all`=readonly 外全需确认；`deny` 永不放行
- ChatEvent 扩展：`confirm?: { callId: string; name: string; args: Record<string, unknown>; risk: Risk }`
- `POST /api/agent/confirm { callId, approve }` → `{ ok, found }`

- [ ] **Step 1: verify-confirm-fn.mjs 失败断言**
1. `classifyCommand`：`"ls -la"`/`"git status"`/`"cat a.txt"` → readonly；`"rm -rf node_modules"`/`"git push"`/`"npm install"`/`"del /f /s x"` → destructive；`"RM -RF /"`（大小写）/`"rm -rf /"`/`"format c:"`/`"sudo x"`/`"dd if=/dev/zero"`/`"reg delete k"`/`"shutdown /s"`/`"taskkill /f"`/`"echo hi > /dev/null"`（含 `> /dev/`）→ deny；`"git add ."` → reversible
2. `classifyTool`：`{name:"read_file"}` → readonly；`{name:"write_file"}` → reversible；`{name:"run_command",args:{command:"rm -rf build"}}` → destructive；`{name:"run_command",args:{command:"rm -rf /"}}` → deny
3. `confirmModeAllows`：`none` 只拒 deny；`writes` 放 readonly；`all` 连 reversible 都确认
4. 异步：`askConfirmation("c1",…)` 后 `resolveConfirmation("c1", true)` → promise true；未 resolve 的 `askConfirmation("c2",…)` 缩短超时可测（导出 `CONFIRM_TIMEOUT_MS` 常量供测试覆盖为 50ms）→ 超时 false

- [ ] **Step 2: verify FAIL（模块不存在）**
- [ ] **Step 3: 实现 confirm.ts + llm.ts 门控 + confirm API**

llm.ts 门控（在 `runTool` 调用处）：
```ts
const risk = classifyTool(name, args);
if (risk === "deny") { result = `工具执行被安全策略拒绝：${denyReason}。请换一种方式或询问学生`; /* yield tool error 事件 */ }
else if (confirmModeAllows(confirmMode, risk)) {
  yield { confirm: { callId, name, args, risk } };
  const ok = await askConfirmation(callId, risk, name, args);
  result = ok ? await runTool(...) : "学生未确认/拒绝了本次操作（为安全未执行）。请说明必要性或换一种方式，不要重复发起同样的调用";
}
```
