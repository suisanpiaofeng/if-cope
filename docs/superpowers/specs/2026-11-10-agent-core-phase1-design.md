## 1. 背景与目标

现状（2026-11-10 代码核实）：`src/lib/llm.ts` 的 `streamChat` **已有 6 轮工具循环骨架**（5 轮带工具 + 1 轮强制文字收尾）、工具事件（start/done/error）经 SSE 推送前端、`ChatPanel.tsx` 有工具时间线（⏳/✅/❌）。**但它是"带工具循环的聊天"，还不是 agent**：

| 缺口 | 表现 |
|---|---|
| 无任务规划 | 复杂任务（"整理资料库并生成三门课的笔记"）没有步骤拆解，模型自由发挥容易漏步骤、重复做 |
| 循环不可观测 | 前端只看到一串工具图标，不知道"进行到第几轮/总共要做什么" |
| 工具无超时 | `executeTool` 无超时控制，`web_search`/`generate_summary` 挂起会卡死整轮 |
| 失败即硬闯 | 工具失败只有一句错误文本回喂，无重试；模型接口断流（网络抖动/上游 5xx）直接抛异常整条回复报废 |
| 循环失控风险 | 并行工具调用逐个执行但事件按 name 匹配（`mergeTool` 以 name 找 run 态），同名工具同轮并发时时间线会错乱 |

目标（G1-G4）：

- **G1 任务规划**：模型先拆解任务生成「任务清单」（todo），执行中实时更新状态；清单对用户**可见、可手动改**；
- **G2 循环升级**：Agent Loop 显式化——每轮带轮次信息与意图说明，用户看得到"它正在做第几步/为什么调这个工具"；
- **G3 健壮性**：工具分类超时、只读工具自动重试、模型调用失败重试、断流可恢复（续跑到上限而非报废）；
- **G4 零回归**：现有单轮问答、引用标注、资料库操作工具、mock 模式行为不变。

## 2. 总体设计

```
用户提问
  │
  ▼
┌─ Agent Loop（升级后）────────────────────────────────────┐
│ 第 0 轮  模型产出任务清单 todo_write([...])  ←── G1        │
│ 第 1..N 轮（N≤8，可配置）                                 │
│   ├─ 模型：意图一句话 + 工具调用          ←── G2（轮次事件）│
│   ├─ 执行器：分类超时 / 只读重试一次       ←── G3          │
│   ├─ 失败 → 错误文本回喂继续循环（不报废）  ←── G3          │
│   └─ todo_write 更新任务状态               ←── G1          │
│ 末轮    强制纯文字总结回答（现有行为保留）                  │
└──────────────────────────────────────────────────────────┘
  │ SSE: delta / reasoning / tool / plan
  ▼
ChatPanel：回答流 + 工具时间线（按 callId）+ 任务面板  ←── G2
```

## 3. 规格明细

### 3.1 任务规划（G1）

**新工具 `todo_write`**（Trae 同名同语义）：

```jsonc
// 参数
{ "todos": [ { "id": 1, "text": "整理未归类资料到对应类目", "status": "pending|in_progress|completed" } ] }
// 每次调用传入完整清单（幂等覆盖），不是增量
```

系统提示词注入硬规则（Trae 行为工程节选，全量写入）：
- 状态三态；**同一时刻只有一个 `in_progress`**；完成立即标记，不批量补标；
- 失败/受阻保持 `in_progress` 并新建描述阻塞的新任务，**永不虚标完成**（测试失败/部分完成/未解决报错 ≠ 完成）；
- 单一直接的小任务（一次移动、一次查询）不必用 todo；拿不准就用；
- 任务粒度具体可执行，复杂任务拆小步。

**存储**：新表 `agent_todos`（会话级，随对话存）：

```sql
agent_todos(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id INTEGER NOT NULL,   -- 归属对话
  item_id INTEGER NOT NULL,           -- 清单内序号
  text TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',
  updated_at INTEGER NOT NULL
)
```

`todo_write` 每次调用整体替换该会话清单（事务内先删后插）。

**任务面板 UI（ChatPanel）**：对话区上方（收起态显示 `☑ 2/5`）可展开为清单列表：
- 每项：状态图标（⬜/🔵/✅）+ 文本；**用户可直接点击状态图标手动改状态、可编辑文本、可删除条目**（用户改动会写回表，下轮模型读取到的即用户改后的——通过把当前清单注入系统提示词实现「人机共写计划」）；
- 只读模型未调用过 todo_write 时不显示面板。

### 3.2 Agent Loop 显式化（G2）

**事件协议升级**（`ChatEvent`，向后兼容，旧字段不动）：

```ts
export type ChatEvent = {
  delta?: string;
  reasoning?: string;
  tool?: ToolEvent;          // 增加 callId、round、intent 字段（可选，旧消费者忽略）
  plan?: { todos: TodoItem[] };   // 新增：清单快照（todo_write 成功后推送）
  run?: { round: number; maxRounds: number; intent?: string }; // 新增：轮次心跳
};
```

- `ToolEvent` 增加 `callId`（唯一调用 ID）、`round`（轮次）、`intent`（模型在调用工具前输出的一句话意图，取该轮 content 首行非空文本）；
- **修复 `mergeTool` 按 name 匹配的缺陷**：改按 `callId` 匹配，同名工具并发不再错乱；
- 工具时间线每条显示：`[第2轮] ⏳ move_source — 将《高数》移到「数学」`（intent 作为说明文字）；
- 循环上限提升为 **8 轮带工具 + 1 轮收尾**（可配置 `IFCOPE_AGENT_MAX_ROUNDS`），触顶时注入一条系统提示"轮次预算即将用尽，请收敛任务并给出总结"，末轮强制文字。

### 3.3 健壮性（G3）

**工具分类超时**（`tools.ts` 执行器包一层）：

| 类别 | 工具 | 超时 | 失败策略 |
|---|---|---|---|
| 只读查询 | list_library / read_source / web_search | 15s（web_search 30s） | 超时/失败**自动重试 1 次**，再失败回喂错误文本 |
| 写操作 | move_source / move_artifact / create_category / todo_write | 10s | **不自动重试**（防重复移动/重复建类目），失败回喂错误文本 |
| 生成 | generate_summary | 120s | 不重试（成本高），失败回喂错误文本 |

实现：`withTimeout(promise, ms, name)`（Promise.race + AbortSignal 传导给 web_search 的 fetch）；超时错误文本明确告诉模型"工具超时，可重试或换路径"。

**模型调用失败重试**：`streamOnce` 的 fetch 对 **429/5xx/网络错误**指数退避重试 2 次（1s/3s）；4xx（非 429）不重试直接报错。**断流恢复**：SSE 连接中途断开且已产出部分内容时，将已累积的 assistant 文本作为 `assistant` 消息回喂、以"继续"续跑一轮（计入轮次预算），最多续跑 2 次；仍失败则保留已产出内容 + 明确的中断提示（不整条报废）。

**循环预算护栏**：单次回复工具调用总数上限 16（8 轮 × 并发 2 内），超限注入"请立即收敛"；防工具死循环（同一工具同参数连续 3 次 → 注入"检测到重复调用，请换策略或停止"）。

### 3.4 系统提示词改造（`agent/system.ts`）

- 保留现有「应用结构/边界/工具清单/资料库状态」（G4 零回归）；
- 新增 `<agent_loop>` 节：说明循环机制（分析→选工具→执行→观察→更新任务→迭代→总结）与"每轮只做一步、做完看结果再决定下一步"（Manus 节选）；
- 新增 `<task_management>` 节：3.1 的 todo 硬规则；
- 新增「输出纪律」：工具调用前用一句话说明意图（供 timeline 显示）；最终回答前先核对清单全部完成。
- 工具清单文本动态化（`listToolsText()` 改为遍历 TOOLS 注册表生成，防再次漂移）。

## 4. 数据模型变更

仅新增 `agent_todos` 表（§3.1），`db.ts` 启动时 `CREATE TABLE IF NOT EXISTS`。无既有表变更。

## 5. 不做的事（本期范围外）

- 用户级偏好/自定义 Prompt（二期）；偏好记忆（二期）；上下文压缩/token 预算 UI（二期）；
- 技能体系、MCP、工具确认三档、密钥加密（三期，其中密钥加密可随时提前插入）；
- 子 Agent/并行任务编排（远期）；
- 工具集扩充（新增工具属于功能需求，不随内核走）。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| todo_write 增加一轮固定开销（每次任务先规划一次） | 小任务系统提示词明确"不必用 todo"；todo 调用与工具调用可在同轮并行发出（API 支持多 tool_calls） |
| 轮次上限 8 对复杂任务不够 | 触顶有收敛提示 + 末轮总结；上限可配置；真实使用后再调 |
| 断流续跑可能重复已完成的工具调用 | 续跑消息里注明"以下是已中断的回复，请继续剩余部分，不要重复已完成的动作"；配合防重复护栏 |
| 面板手动编辑清单后模型不认 | 清单每轮从表读出注入提示词（§3.1），人机共写同一数据源 |
| 不同模型 function calling 质量参差 | 保留现有"上游不支持 tools 则降级纯文本"逻辑；deepseek/glm/qwen 真机过一遍验收 |

## 7. 验收标准

1. 提问"把未归类的资料整理好并给数学资料生成复习笔记"：模型先出任务清单（面板可见），逐项执行并实时更新状态，最终核对完成；
2. 任务面板显示与模型一致，手动改状态/文本后下轮模型感知（对话中让它复述清单可验证）；
3. 工具时间线按轮次显示，含意图说明；同名工具并发不串行错乱；
4. 断网/上游 5xx 模拟：模型调用自动重试；中途断流不整条报废，有续跑或明确中断提示；
5. 工具超时（模拟慢查询）：该工具报超时、模型收到提示后继续，整轮不卡死；
6. 同参数重复调用 3 次触发护栏提示；
7. 回归：单轮纯问答、引用标注、7 个资料库工具、mock 模式、未配置模型提示全部照旧；
8. `npm run build` 通过。
