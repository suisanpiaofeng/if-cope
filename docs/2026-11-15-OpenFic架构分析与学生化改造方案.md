# IF.Cope 学生化改造 · OpenFic 架构对齐方案（2026-11-15）

> 依据：syrizelink/OpenFic 源码剖析（本地 clone：`../openfic-ref`，v0.13 系）+ 产品诉求（抄 OpenFic 界面架构、功能换成学生域）。本文三部分：①OpenFic 架构 ②想法审查（问题/盲区） ③详尽方案。

## 〇、定稿决策（2026-11-15 与用户逐条确认）

| 决策点 | 结论 |
|---|---|
| 项目粒度 | **自由工作空间**：只填名称（+可选描述），无模板不限粒度（一门课/一次 PPT/一张海报均同）；课程骨架降级为 AI 能力（对话里让 AI 建），不进 UI 流程 |
| 对话归属 | 会话**归属创建时的项目，不可改** |
| 检索范围 | 对话默认检索**当前项目**；知识地图答题可**多选项目**（存为该地图的检索范围） |
| 资料模块 | **取消**（用户判断无独立价值）：文件管理全量并入**项目视图** |
| 底部芯片 | **槽位语义**：× 只移除快捷槽位，不删项目；删项目进项目管理页强确认 |
| 对话域 | 两个：**工作对话**（项目视图/文献翻译等共享同一份历史）＋**解题对话**（知识地图独享历史与产物） |
| 知识地图归属 | **全局无归属**（不绑项目）；多选项目仅为出题检索范围；产物只在解题答疑模块管理 |

## 一、OpenFic 架构剖析

### 1.1 技术栈与分层
- **后端**：Python / FastAPI / SQLModel(SQLite) / alembic 迁移；模块：`agent_runtime`（Agent 内核）、`storage`（models/repos/services）、`retrieval`（检索索引）、`memory`、`skills`、`prompts`、`background`
- **前端**：Vite + React + TS；`features/` 按域分：app-shell（布局壳）/ projects / world-info / characters / writing / assistant / dashboard / settings / prompt-chains
- **多端**：desktop 壳、mobile（RN）、Docker/pip 分发；状态栏 WebSocket「已连接」

### 1.2 数据模型（Project 为根）
```
Project(id,title,description,word_count,chapter_count,cover_path)
 ├─ Volume → Chapter（章节，含 summary/index）
 ├─ WorldInfo → WorldInfoEntry（世界书条目，含 tokens/enabled 开关）
 ├─ Character + CharacterRelationship
 ├─ Note（笔记）
 ├─ Skill + SkillReferenceDoc（技能：YAML 定义 id/name/summary/content/references/enabled）
 ├─ PromptEntry / PromptChainVersion（提示词链）
 ├─ Task + TaskMessage（AI 对话任务：project_id 外键、mode、token 用量、
 │     current_revision_id/current_message_id（revision 快照回滚）、is_running、收藏）
 └─ Revision/Commit（实体快照体系）、agent_memory/agent_rule、retrieval_index、
     writing_activity_event、llm_audit_log
```
要点：**一切挂在项目下**；对话（Task）也带 project_id + revision checkpoint；技能是数据（YAML+引用文档）不是代码。

### 1.3 布局系统（截图对应）
```
[AppSidebar 导航轨 64↔232px] [模块主区 Outlet] [RightSidebar] [StatusBar]
      └─ 底部 recent-projects-nav：最近项目槽位（彩色首字母、×移除槽位、点击进 /projects/:id）
模块主区三栏：列表栏（project-select-field 项目下拉＋搜索/导入/排序＋条目列表[Tokens/开关/拖拽]）
             → 编辑区（markdown-editor＋多标签＋工具栏/字数/已保存）
             → RightSidebar（通用右栏：assistant host＝「最近任务」列表＋对话输入，或实体编辑器 tabs）
```
- `RightSidebar` 是通用容器：`assistant-sidebar-host` 把 AI 对话挂进右栏；任务列表=历史会话
- `project-select-field`/`project-grid-selector`：每模块顶部项目选择器（图2）与项目网格卡（图1）
- **最近项目是"槽位"语义**：×=移出槽位（不删项目）；进项目即回到槽位——用户理解的"可手动删除、点击再次生成"即此

### 1.4 Agent 体系（agent_runtime）
- runner/graph/plan（任务规划）/streaming/fork（会话分叉）/revisions（回滚快照）/tool_call_recovery（工具失败恢复）/session persistence
- **工具**（impls/）：chapter 14 个（卷章增删改/搜索/diff 预览/索引）、file、note、skill、context、interaction、orchestration、plan、web_fetch/web_search；`permission_metadata.py`＝工具权限元数据（分级确认的影子）
- **技能**：YAML（id/name/summary/content/references/enabled）＋token 计数，按启用态进上下文

### 1.5 值得抄 vs 不抄
| 抄（结构） | 不抄（域内容） |
|---|---|
| 导航轨＋最近项目槽位＋状态栏 | 世界书/角色/提示词链（写作域） |
| 模块三栏（列表/编辑/右对话）＋项目选择器 | 章节卷宗结构（换成文件树） |
| Task 带 project_id＋checkpoint＋token 统计 | 小说编辑器工具栏（换学生文档工具） |
| 条目开关＋Tokens 计数（→入库开关＋块数） | 桌面菜单栏/多实例（我们是 web） |
| 技能=YAML/引用文档数据化 | —— |

## 二、想法审查（问题与盲区）

**成立的部分**：四栏布局（功能轨/列表/预览编辑/右对话）与我们现有工作台同构，改造成本主要在**项目维度与导航**，不是推翻布局；解题答疑地图单独管理（我们 qa-map 本就不落资料）；翻译产物回同项目合理。

| # | 问题/盲区 | 风险 | 解法方向（本文 §3 落点） |
|---|---|---|---|
| 1 | **"项目"粒度未定义**：一门课=项目？考研=项目？大创=项目？OpenFic 项目=一部小说（强边界），学生项目边界模糊 | 组织混乱 | 项目模板（课程/考试/课题/自定义），§3.2 |
| 2 | **跨项目检索缺失**："agent 在当前项目中检索"——但"我所有资料里搜X"是学生高频需求；知识不像小说设定可以隔离 | 最常用能力退化 | 对话框检索范围开关（本项目/全部），§3.6 |
| 3 | **与 P3 统一树的关系没交代**：`资料/`12 个文件、现有目录树怎么办 | 又出两套组织 | 项目=顶层目录，幂等迁移延续 P3，§3.3 |
| 4 | **工作台删去后的功能去向**：便签生成/AI 归类/勾选问答/产物浏览会丢 | 功能回退 | 功能迁移矩阵，§3.5 |
| 5 | **底部芯片"可手动删除"歧义**：×到底是删项目还是移槽位？ | 误删项目 | 槽位语义（×只移除芯片）＋项目删除进管理页强确认，§3.4 |
| 6 | **资料 vs 产物边界**：产物笔记落树后算资料吗？项目模块与资料模块都看文件，功能重叠 | 两个模块傻傻分不清 | 资料=文件工作区（全文件带产物徽标）；项目模块=总览仪表（统计/产物清单/快入口），§3.4 |
| 7 | **对话无项目归属**：threads 切项目后历史串台 | 上下文混乱 | threads.project_id＋项目锚定，§3.6 |
| 8 | **翻译产物"同项目位置"细节**：译文现入库为资源但路径不跟原文 | 目标落空 | 译文 path=原文同目录，§3.5 |
| 9 | **设置/技能/MCP/hooks 去处没提**（我们 P0-P2 的 harness 能力） | 能力丢失 | 齿轮设置入口保留收纳，§3.4 |
| 10 | **知识地图"单独管理"的范围**：地图列表/多地图/项目过滤要界定 | 实现发散 | 解题答疑模块=地图列表（按项目）+画布+对话，§3.5 |

## 三、详尽方案

### 3.1 信息架构（导航轨自上而下）【定稿】
```
≋ IF.Cope
├─ 项目          ← 项目管理页（卡片网格、新建（仅名称）、搜索、删除强确认）
├─ 解题答疑      ← 知识地图（全局地图列表＋多选项目检索范围＋画布＋解题对话）
├─ 文献翻译      ← 翻译（项目选择器＋任务列表＋双语对照＋工作对话）
──────────────
[最近项目槽位×N]  ← 彩色首字母、×移除槽位、点击进项目视图
──────────────
⚙ 设置           ← 模型/参数/技能/MCP/hooks/安全（齿轮常驻）
```
- **项目视图**（点项目卡/芯片进入）：`[文件树 | 预览编辑 | 工作对话]` 三栏——文件管理（原资料模块全部能力）在此；项目内查看资料文件＋产物文件（产物徽标）
- **两个对话域**：工作对话（跨模块共享历史，会话锚定创建项目不可改，检索默认当前项目）；解题对话（知识地图独享）
- 布局骨架：`[导航轨] [列表/树栏] [预览+编辑] [对话栏]`；项目管理页例外（全宽卡片网格）

### 3.2 项目模型【定稿】
- 表 `projects(id, title, description, created_at, updated_at)`；**无类型无模板**（自由工作空间）
- **项目 = 树内顶层目录**（延续 P3"位置=路径"）：创建即建目录；结构由学生/AI 自组织（AI 建骨架作为工具能力存在，非 UI 流程）
- 归属列：`sources.project_id`、`artifacts.project_id`、`threads.project_id`（path 前缀派生＋显式列双轨，写路径时同步）

### 3.3 迁移（幂等，延续 P3 风格）
1. 顶层目录（`资料/`、`冒烟高数/`、`项目/`…）→ 逐个升级为项目记录（type=课程，title=目录名）；`资料/` 平铺文件归入「未分配」项目（id 固定 sentinel）
2. sources/artifacts 补 project_id（按 path 前缀）；threads 补 project_id（历史线程→「未分配」）
3. 向量块不动（内容未变）；`/api/projects/migrate` 幂等（按 project_id IS NULL 过滤）

### 3.4 模块规格【定稿】
- **项目页**：卡片（标题/统计：N 份资料·M 份产物）＋新建（仅名称）/搜索/排序；点卡进项目视图；删除=destructive 强确认
- **项目视图**（原资料模块并入）：文件树（P3 FileTree 平移：徽标/筛选/入库开关/行操作）＋预览编辑（多标签＋diff）＋工作对话
- **解题答疑页**：地图列表（**全局**，不按项目过滤）＋每图检索范围**多选项目**（存为地图设置）＋画布（现 solve 全功能保留）＋**解题对话**（独立历史）；qa-map 产物只在本模块管理
- **文献翻译页**：翻译任务列表＋双语对照预览（保留）＋工作对话；**译文产物 path=原文同项目目录**
- **最近项目槽位**：localStorage 槽位（N=6），进入项目自动入槽，×移除槽位
- **设置**：抽屉收纳全部（模型档/参数/技能/MCP/hooks/confirmMode/commandPolicy）

### 3.5 功能迁移矩阵（工作台下线）
| 现功能 | 去向 |
|---|---|
| 勾选资料 RAG 问答 | 资料页右栏对话（勾选语义保留） |
| 便签生成（generate_summary） | 资料页对话＋产物落树（P3-3 已落） |
| AI 归类（move_source） | 资料页（类目=文件夹语义不变，移动即移文件） |
| 产物预览 | 资料树产物徽标＋项目页产物清单 |
| 知识地图 | 解题答疑页（独立管理） |
| 文献翻译 | 文献翻译页（产物回同项目） |
| harness（文件工具/命令/MCP/hooks/技能） | 设置＋Agent 工具不变（项目=上下文锚点） |

### 3.6 Agent 项目锚定【定稿】
- 当前项目 → system prompt 注入 `<project>`（项目名/树摘要）＋RAG 默认范围＝当前项目已入库文件＋文件工具根＝项目目录
- **检索范围**：工作对话默认当前项目；**解题对话可多选项目**（地图的检索范围设置）；文件树搜索默认项目内
- **对话域**：工作对话=全局共享一份历史（会话带创建项目锚点，不可改）；解题对话独立历史、产物独立管理
- 会话归属展示：工作对话列表显示所属项目徽标（不做过滤，共享一份）

### 3.7 分批实施
| 批次 | 内容 | 产出 |
|---|---|---|
| **P4-1 项目数据层** | projects 表/模板/归属列/迁移脚本/项目 CRUD API/项目=目录同步 | 数据就绪＋迁移冒烟 |
| **P4-2 布局骨架** | 导航轨＋最近项目槽＋项目选择器＋四栏框架＋项目管理页＋设置收纳 | 新壳可导航 |
| **P4-3 模块搬家** | 项目视图/解题答疑/文献翻译三页组装（现组件平移）＋工作台下线＋资料模块取消＋迁移矩阵落地＋译文归位 | 功能无回退 |
| **P4-4 锚定与打磨** | 对话项目锚定＋检索范围开关＋threads.project_id＋状态栏＋验收 | 完整体验 |

### 3.8 风险
- **数据迁移**：项目=目录的幂等迁移是最大风险点——沿用 P3 迁移模式（path IS NULL 过滤＋重跑安全）
- **组件平移**：solve/translate 页内嵌复杂（1163 行），搬家以"路由壳包旧组件"方式最小改动
- **两套分组残留**：solve/translate 页旧类目视图在 P4-3 统一切到文件树，避免长期共存
