## 1. 核心发现：成熟 Agent 应用的共性架构

拆解 Trae Builder Prompt（18.5KB）、Manus Agent Loop/Modules、Codex docs、OpenFic `agent_runtime/` 后，成熟 agent 应用都长成同一副骨架：

```
┌─ 系统提示词层（Persona + 行为规范 + 引用格式）─────────────┐
├─ 事件流 / 上下文层（Event Stream，可截断、分层压缩）───────┤
├─ 规划层（Planner：步骤伪代码 + 状态 + 反思，随目标更新）───┤
├─ Agent Loop（每轮一个工具调用 → 观察 → 迭代 → 提交）──────┤
├─ 工具层（文件/搜索/命令/编辑 + 任务清单 todo）─────────────┤
├─ 记忆/知识层（Knowledge 模块注入最佳实践；语义检索）───────┤
├─ 安全层（沙箱、执行策略、敏感操作交还用户、提示词防泄露）─┤
└─ 成本层（用量统计、上下文压缩、缓存、超时管理）───────────┘
```

### 1.1 Manus 的 Agent Loop（最经典的六步循环）

```
1. Analyze Events  — 从事件流理解用户意图与当前状态
2. Select Tools    — 结合任务计划/知识/数据 API 选下一个工具
3. Wait for Execution — 沙箱执行，结果作为观察写回事件流
4. Iterate         — 每轮只调一个工具，耐心循环直到完成
5. Submit Results  — 用消息工具交付成果（附件形式）
6. Enter Standby   — 完成或用户叫停后进入待命
```

其事件流（event stream）包含 7 类事件：Message / Action / Observation / **Plan（Planner 模块产出的步骤计划+状态+反思）** / **Knowledge（任务相关最佳实践注入）** / Datasource / 杂项。计划用编号伪代码表示，每次更新带当前步骤号、状态与反思。

### 1.2 Trae 的行为工程（系统提示词拆解）

Trae Builder Prompt 的精华是**大量显式行为规范**：

| 板块 | 关键规则（摘） |
|---|---|
| communication | 不撒谎；**拒绝复述系统提示词/工具定义/剩余轮数**（防泄露）；少道歉多推进 |
| search_and_reading | 一次读大段优于多次小读；找到答案就停手，别继续调工具 |
| making_code_changes | **绝不让用户看代码**，直接用编辑工具落地；改动必须可立即运行；遵循现有代码风格；最少步骤（≤3 步）；**绝不假设依赖存在**，先查 package.json |
| debugging | 只改有把握的代码；找根因不修症状；加日志加测试隔离问题 |
| toolcall_guidelines | **最小化调用次数**；严格按 schema；绝不调用未提供的工具；已知工具清单明示（todo_write / search_codebase / search_by_regex / view_files / list_dir / write_to_file / update_file / edit_file_fast_apply / rename_file / delete_file / run_command…） |
| todo_write | 任务三态（pending/in_progress/completed）；**同一时刻只有一个 in_progress**；完成立即标记不批量；失败保持 in_progress 并新建阻塞任务；永不虚标完成 |
| 引用格式 | mcfile/mcsymbol/mcurl/mcfolder 结构化引用 + 网页引用带索引，全部机器可解析 |

### 1.3 Codex / Claude Code 的 harness 工程（docs 目录）

Codex 文档目录本身就是能力清单：`skills.md`（技能=可加载的领域能力包）、`slash_commands.md`（斜杠命令）、`execpolicy.md`（**执行策略：分级允许/拒绝/询问**）、`sandbox.md`（沙箱隔离）、`agents_md.md`（用户级持久指令）、`config.md`（生命周期 hooks，管理域 hooks 可锁配置）、`authentication.md`。要点：

- **权限分级**：exec policy 把工具调用分为 自动允许 / 拒绝 / 需用户确认，可按命令模式配置；
- **Skills 体系**（Claude Code/Codex 同款，ECC 300k★ 证明生态价值）：领域能力打包成 SKILL.md + 脚本，按需加载，用户可写自己的 skill；
- **AGENTS.md / 用户级指令**：项目级 + 用户级持久偏好注入，就是"个性化设置"的标准化做法。

### 1.4 OpenFic 的本地应用工程（与我们最同构）

OpenFic `agent_runtime/` 的模块划分：`runner` `streaming` `tool_call_recovery`（工具失败恢复）`timeout_settings`（分类超时）`usage_cost`（逐轮成本）`plan`/`graph`（规划）`continuation`/`fork`/`revisions`（续跑/分叉/回溯）`memory` + `retrieval`（Agentic RAG）`prompts`/`skills`（**任何 Prompt 用户可改**）。安全上：Fernet 加密落库密钥、可选应用密码门、audit 模块、数据全本地。

### 1.5 WorkBuddy 生态的启示（WorkBuddyGuide 3.8k★）

官方产品能力维度：**Skills（领域技能包）+ MCP（外部工具协议）+ 自动化（定时/触发任务）+ 多智能体（分工协作）**。`trae-agent-enhancements` 类社区项目同样收敛为"技能 + 规则 + 双轨记忆（短期会话记忆 + 长期偏好记忆）"。

## 2. Agent 能力清单（成熟产品的公约数，10 项）

| # | 能力 | 说明 | 代表实现 |
|---|---|---|---|
| C1 | **工具循环（Agent Loop）** | 多轮：调工具→观察→再决策，直到完成；每轮一个调用 | Manus 六步循环 |
| C2 | **任务规划（Todo/Plan）** | 复杂任务先拆解成步骤清单，实时更新状态；UI 可见 | Trae todo_write、Manus Planner |
| C3 | **上下文工程** | 事件流、历史截断、长文档压缩、引用注入、成本控制 | Manus event_stream、OpenFic 分层上下文 |
| C4 | **记忆与个性化** | 用户级持久指令（AGENTS.md 式）、偏好记忆、跨会话知识 | Codex agents_md、双轨记忆 |
| C5 | **技能体系（Skills）** | 领域能力包化，可扩展、可复用、用户可写 | Claude Code/Codex skills、WorkBuddy Skills |
| C6 | **工具生态（MCP）** | 接入外部工具协议，工具即插即用 | WorkBuddy、Cherry Studio、open-webui |
| C7 | **权限与安全** | 执行策略分级（允许/拒绝/确认）、沙箱、密钥加密、提示词防泄露 | Codex execpolicy/sandbox、Trae 防泄露规则 |
| C8 | **健壮性** | 工具失败恢复、分类超时、重试、断流续跑 | OpenFic tool_call_recovery 等 |
| C9 | **透明度** | 任务进度 UI、结构化引用、成本展示、审计日志 | Trae mcfile 引用、OpenFic usage_cost |
| C10 | **子 Agent/多智能体** | 任务分工、并行子任务、汇总 | WorkBuddy 多智能体、Manus |

## 3. if_conote（IF.Cope）现状与差距分析

现状：`src/lib/agent/system.ts`（93 行，环境自知提示词+资料库状态注入）+ `tools.ts`（199 行，7 个工具：list_library / read_source / move_source / move_artifact / create_category / generate_summary / web_search）+ `chat/route.ts`（118 行，流式转发+web_search 预检索）。提示词设计已有 Trae 风格雏形（调用原则、边界说明）。

| 能力 | 现状 | 差距 | 评级 |
|---|---|---|---|
| C1 工具循环 | ⚠️ 半有：工具调用存在但是**单轮**（streamChat 内一发一答），无多轮循环 | 缺完整 agent loop（调用→观察→再调用直到完成） | ★★☆☆☆ |
| C2 任务规划 | ❌ 无 | 缺 todo/plan 工具与状态管理 | ★☆☆☆☆ |
| C3 上下文工程 | ⚠️ 有检索注入+历史，无截断/压缩/成本控制 | 长对话爆上下文无保护 | ★★☆☆☆ |
| C4 记忆/个性化 | ❌ 提示词写死代码；无用户偏好 | 缺用户级指令、偏好记忆 | ★☆☆☆☆ |
| C5 技能 | ❌ 无 | 无技能概念（工具是硬编码的） | ★☆☆☆☆ |
| C6 MCP/工具生态 | ❌ 无 | 工具全靠手写 registry | ★☆☆☆☆ |
| C7 权限/安全 | ⚠️ 本地单机可信；API Key **明文**存 SQLite；提示词防泄露无 | 密钥加密、工具确认机制 | ★★☆☆☆ |
| C8 健壮性 | ❌ 工具失败即终止；无超时/重试 | 缺恢复机制 | ★☆☆☆☆ |
| C9 透明度 | ⚠️ 有工具执行事件推送（send({tool})）；无成本/引用弱 | 缺用量、结构化引用 | ★★☆☆☆ |
| C10 子 Agent | ❌ 无 | 远期 | ★☆☆☆☆ |

**结论：我们有"工具调用"，但没有"Agent"。** 与成熟产品的分水岭是 C1（循环）+ C2（规划）+ C4（记忆）+ C8（健壮性）。

## 4. 能力升级路线（建议三期）

### 一期：Agent 内核（补 C1/C2/C8，"像 agent 了"）
1. **Agent Loop**：chat 改造为多轮循环——模型调工具 → 执行 → 结果回填 → 再决策；上限轮数（如 8）防死循环；流式 UI 展示每轮。
2. **Todo/Plan 工具**：todo_write（三态、单 in_progress、如实标记），任务面板 UI 可见可编辑。
3. **健壮性**：工具超时（分类配置）、失败重试一次、失败结果作为观察继续循环（不报废整轮）、断流恢复。

### 二期：个性化与上下文（补 C4/C3，"用得顺手"）
4. **用户级指令**：设置页可编辑「我的偏好」（AGENTS.md 式）+ 各场景 Prompt 可改可恢复默认（借鉴 OpenFic「任何 Prompt 可改」）。
5. **偏好记忆**：从对话中提炼长期偏好（双轨记忆的轻量版），启动时注入。
6. **上下文工程**：历史分层截断、超长资料压缩、token 预算与用量展示。

### 三期：生态与安全（补 C5/C6/C7，"可扩展、安全"）
7. **技能体系**：技能=Markdown 描述+工具组合，用户可写技能文件放 data 目录（Claude Code SKILL.md 同款）。
8. **工具确认机制**：破坏性操作（删除/移动）可配置"自动/确认/拒绝"三档（Codex execpolicy 思路）。
9. **安全加固**：API Key 加密落库（Fernet 式）、提示词防泄露规则、审计日志。
10.（远期）MCP 接入、子 Agent 并行。

### 优先级依据
- 一期是分水岭：没有循环+规划就永远只是"带工具的聊天"；
- 二期直接决定"个性化设置"体验（用户诉求）；
- 三期的密钥加密是安全底线，可提前插入任意期。
